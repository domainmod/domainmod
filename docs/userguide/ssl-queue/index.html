As of v4.27.0, the SSL Queue imports your SSL certificates for you. Paste a list of hostnames, and DomainMOD connects to each site, reads the certificate it serves, and adds it as an SSL certificate with its expiry date and issuer. New certificates are linked to their domain when DomainMOD has just one record of that domain.

Requirement

The SSL Queue is processed by the SSL Queue Processing task, so you must set up the cron job that comes with DomainMOD (Docker installs already run it).

Adding SSL Certificates Automatically

  1. Click SSL Certificates on the main menu.

  2. Choose Add SSL Certificates Automatically from the menu beside the Add SSL Certificate button. Before you have any SSL certificates, it's a button on the page instead.

  3. Paste in up to 1,000 hostnames, one per line. Each line can be a hostname, such as example.com, or an https:// address.

  4. Choose the SSL Provider Account. Match each certificate's issuer (recommended) finds or adds the SSL provider for each certificate's issuer, and uses your account there, or adds an account named "SSL Import". Then choose the Owner (used with issuer matching, since a chosen account has its own owner), and, under Defaults for New Certificates, the Certificate Type, IP Address, and Category. The Owner, IP Address, and Category start on Same as the Domain, which gives each certificate its domain's values, or your SSL defaults for a hostname whose domain isn't in DomainMOD.

  5. Click the Add SSL Certificates button, and you'll be taken to the Import Queue page, where you can follow the progress of your imports.

Only port 443 is checked, and only public sites can be reached. A hostname whose domain is still in the Domain Queue waits up to 7 days for it, and is then checked anyway. A certificate that's already in DomainMOD isn't added again: that's a live certificate with the same hostname, or the very same certificate. An expired record with the same hostname doesn't stop the new certificate being added. To update an existing certificate's expiry date, use Refresh on its edit page (see below).

You can also import certificates while you add domains: when you add domains with the Domain Queue, Also import each domain's SSL certificate (on by default) adds each domain's site to the SSL Queue. Only the domains you paste are looked up, not the ones a registrar's API supplies.

The Import Queue

The Import Queue page shows the Domain Queue and the SSL Queue, one after the other, each with its own buttons. While either queue has entries, you can open it with Import Queue on the main menu.

For each hostname, the SSL Queue shows its status, such as Pending, Processing, Retrying, Waiting for the Domain, Imported, or Failed, with the reason when there is one. An imported certificate that has expired or isn't trusted gets an Expired or Not trusted badge. A hostname is tried up to three times before it fails. Use Retry Failed to put failed hostnames back in the queue (a hostname whose chosen account or other setting has since been deleted has to be added again instead), Clear Completed to remove the finished ones, and Export to download the list.

Note

A new certificate needs a fee for its SSL provider and type, like any other SSL certificate. Until the fee is added, it's hidden from the SSL Certificates list (see Missing Fees in Assets -> SSL Fees).

Adding an SSL Certificate Manually

First add an SSL provider and an SSL provider account, if you haven't already. Then click SSL Certificates on the main menu, and click the Add SSL Certificate button. Enter the certificate's Host / Label, such as example.com, and fill in its details. As of v4.27.0, a certificate doesn't need a domain: set Domain to None for one that isn't for a domain in DomainMOD. When you delete a domain, its SSL certificates are kept without a domain.

Refreshing an SSL Certificate

As of v4.27.0, an SSL certificate's edit page has a Refresh button near the top. It reads the certificate the site serves now, and updates the expiry date and status when they've changed, with a note saying what changed. A pending status is kept, and the SSL provider, account, type, and fee aren't changed. Refresh needs the certificate's Host / Label to be the hostname it's installed on, such as example.com, and part of the certificate's domain, if it has one.
