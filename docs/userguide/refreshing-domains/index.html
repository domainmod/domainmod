DomainMOD can look up a domain's current details and update them for you, either when you click Refresh on the domain's edit page (as of v4.25.0), or automatically with the Refresh Domains task (as of v4.27.0). The changes a refresh makes are recorded in the Change History.

Refresh

On the domain's edit page, click the Refresh button near the top, and DomainMOD will look up the domain's current details and update them straight away, listing what changed.

If your registrar account uses a supported registrar API with its API details filled in, DomainMOD uses the API, which can update the expiry date, DNS servers, WHOIS privacy, and auto-renewal status (some registrars' APIs don't report all of these, and anything not reported is left as it is). Otherwise, or if the API can't be used, DomainMOD uses public RDAP and WHOIS data instead, which updates the expiry date and DNS servers, but not WHOIS privacy or auto-renewal. As of v4.27.0, Refresh also checks the transfer lock and registry status using RDAP where it's available, whichever source updates the other details, and looks up the domain's live DNS.

To avoid overloading your registrar and the RDAP and WHOIS servers, there's a short wait between refreshes. If you've changed the expiry date, DNS servers, WHOIS privacy, auto-renewal, or notes without saving, DomainMOD asks before a refresh replaces your changes. Read-only users don't see the Refresh button.

Automatic Refreshes

The Refresh Domains task refreshes your live domains (every domain that isn't Expired or Sold) a few at a time, the same way Refresh does, and records its changes in the Change History as Scheduled Refresh. It's off by default, so an administrator needs to enable it in Administration -> Task Scheduler, and the cron job must be set up (Docker installs already run it). See Task Scheduler for how it checks each domain.

Each live domain's Change History section shows its automatic check status, such as when it was last checked and when its next check is due.

Registry Status and Transfer Lock

As of v4.27.0, Refresh reads each domain's registry status codes from RDAP, along with its transfer lock: Locked, Not Locked, Unknown (the registry didn't report a clear status, or RDAP isn't available for the TLD), Couldn't Check (no status could be read yet), or Not Checked. Domains added with the Domain Queue's RDAP import get them too. Some country-code registries don't use transfer locks.

The domain's edit page has a Registry Status section, the Domains list has a Registry Status filter, and you can add a Transfer Lock column in Settings -> Display Settings. A domain that the registry has on hold, or is deleting or restoring, gets an On Hold, Being Deleted, or Being Restored badge. For live domains expiring in the next 30 days, or already past their expiry date, the At-Risk Domains report (and the Dashboard's at-risk count) also covers ones with the transfer lock off (Transfer Lock Off, for domains not yet expired) and ones on hold or being deleted or restored (Registry Hold or Deletion).

Live DNS

As of v4.27.0, after each refresh (clicked or automatic), when there's time left, DomainMOD looks up the domain's live name servers, IP addresses (for the domain and its www name), and mail servers. These lookups go through your server's own DNS resolver, so whoever runs that resolver can see the names being checked.

DomainMOD compares the live name servers with the domain's DNS profile, and the live addresses with its IP Address. Live DNS only reports what it finds. It never changes the domain, its DNS profile, or its IP Address.

The Live DNS section on the domain's edit page shows what was found and how it compares. When one of your DNS profiles or IP Addresses matches what's live, Use it picks it in the edit form (click Save to keep it), and Add this IP Address opens the Add IP Address form with a live address that isn't in DomainMOD yet filled in. Changes to the live name servers and addresses are recorded in the Change History.

On the Domains list, you can add a Live DNS column in Settings -> Display Settings, and use the Live DNS filter to find domains whose name servers or IP address differ, that have no DNS, or whose check failed or hasn't run. The Domains export includes it too.
