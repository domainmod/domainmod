Custom Fields

Custom Fields help extend the functionality of DomainMOD by allowing the user to create their own data fields. For example, if you wanted to keep track of which domains are currently setup in your Analytics software, you could create a new Analytics check box field and start tracking this information for each of your domains. Combine Custom Fields with the ability to update them with the Bulk Updater*, and the sky's the limit in regards to what data you can easily track!

When you export your domain or SSL certificate data, the information contained in your custom fields will automatically be included in the exported data.

Custom Field Types: Check Box, Date, Text Field, Text Area, Time Stamp, URL

Note

As of v4.13, DomainMOD has the ability to display your Custom Field data on the main Domain and SSL Certificate pages.

Note

* The Bulk Updater currently only allows you to update Custom Domain Fields, but not Custom SSL Certificate Fields.

Task Scheduler

The Task Scheduler (Administration -> Task Scheduler) runs DomainMOD's system jobs, such as processing the Domain Queue, sending expiration emails, and building the Data Warehouse. In order for it to work, you must set up the cron job that comes with DomainMOD, and you can also limit who can run it with a Task Scheduler Key. If you installed DomainMOD using Docker, you don't need to set up the cron job, since the container already runs the Task Scheduler every 10 minutes.

As of v4.26.0, Last run of cron.php on the Task Scheduler page shows when cron.php last ran, or Never. When you upgrade to v4.26.0, Last run of cron.php is set to the time of the upgrade if the Task Scheduler had run before, so a working cron job isn't reported as stopped before its next run. If any tasks are enabled and cron.php last ran more than two hours ago, administrators see a warning on the Dashboard and the Task Scheduler page, with a link to the cron job instructions. Until it runs again, expiration emails and the Domain Queue only run when you use Run Now. If tasks are enabled and cron.php has never run, the Task Scheduler page shows a note explaining how to set it up, and administrators see it on the Dashboard too whenever the Getting Started checklist isn't shown. If every task is disabled, neither page warns you.

As of v4.25.0, each daily task runs at the same local time all year, including across daylight saving time changes. When you set a daily task's run time, it's saved in your own time zone (from your user settings), and the Task Scheduler page shows each daily task's run time along with its time zone. Changing your time zone later doesn't move tasks that are already set, so set their run times again if you want them to follow your new time zone. When you upgrade to v4.25.0, existing daily tasks keep running at the same moment, using the time zone of the user who installed DomainMOD (or of the first administrator).
