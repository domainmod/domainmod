Custom Fields

Custom Fields help extend the functionality of DomainMOD by allowing the user to create their own data fields. For example, if you wanted to keep track of which domains are currently setup in your Analytics software, you could create a new Analytics check box field and start tracking this information for each of your domains. Combine Custom Fields with the ability to update them with the Bulk Updater*, and the sky's the limit in regards to what data you can easily track!

As of v4.27.0, there are custom fields for hosting services too, in Administration -> Custom Hosting Fields, alongside Custom Domain Fields and Custom SSL Fields.

When you export your domain, hosting, or SSL certificate data, the information contained in your custom fields will automatically be included in the exported data.

As of v4.27.0, you can also filter the Domains and SSL Certificates lists by custom field, in the Custom Fields section of the filter panel. A check box field has a Value menu (Yes or No). Text fields, text areas, and URLs have a Contains box, and dates and time stamps have a Between range. Every type except check boxes also has a Filled In menu (Filled in or Empty).

Custom Field Types: Check Box, Date, Text Field, Text Area, Time Stamp, URL

Note

As of v4.13, DomainMOD has the ability to display your Custom Field data on the main Domain and SSL Certificate pages, and as of v4.27.0 on the main Hosting page.

Note

* The Bulk Updater currently only allows you to update Custom Domain Fields, but not Custom Hosting Fields or Custom SSL Certificate Fields.

Task Scheduler

The Task Scheduler (Administration -> Task Scheduler) runs DomainMOD's system jobs, such as processing the Domain Queue, sending expiration emails, and building the Data Warehouse. In order for it to work, you must set up the cron job that comes with DomainMOD, and you can also limit who can run it with a Task Scheduler Key. If you installed DomainMOD using Docker, you don't need to set up the cron job, since the container already runs the Task Scheduler every 10 minutes.

Each task can be disabled or enabled, and Run Now runs it straight away. As of v4.27.0, Disable All at the top of the page disables every task that isn't running at the time, and once they're all disabled, Enable All turns them back on. These are the tasks, in the order the Task Scheduler page lists them:

  • Domain Queue Processing (every 5 minutes): looks up the domains in the Domain Queue and adds them to DomainMOD.
  • SSL Queue Processing (every 5 minutes): reads the certificates of the sites in the SSL Queue and adds them to DomainMOD.
  • Send Expiration Email (daily): emails everyone who's subscribed about upcoming domain, hosting service, and SSL certificate renewals. Users can subscribe in their User Profile, and administrators can set the From address and the number of days the email covers in System Settings.
  • Update Conversion Rates (daily): gets the current currency conversion rates and updates every user's costs. Users can set their currency in their User Profile.
  • System Cleanup (daily): converts domains to lowercase, checks that every TLD is correct, and records the status of each domain in your segments, which keeps segment filtering up to date. It also checks the domain, SSL certificate, and fee data against each other, deletes unused domain and SSL fees, updates the hosting services' costs from their fees, and removes change history older than the time set in System Settings.
  • Check For New Version (daily): checks whether a newer version of DomainMOD is available to download.
  • Data Warehouse Build (daily): rebuilds the Data Warehouse, so it has the latest information from your servers.
  • Refresh Domains (every 10 minutes, off by default): as of v4.27.0, checks the expiry date and DNS servers of each live domain (every domain that isn't Expired or Sold), a few domains at a time, and records any changes in the Change History as Scheduled Refresh. When DomainMOD supports the registrar's API and the domain's registrar account has its API details filled in, the registrar's API is used, and it can also update WHOIS privacy and auto-renewal. Otherwise, or if the API can't be used, public RDAP data is used, or WHOIS for TLDs without RDAP, and an RDAP server can pass the lookup on to another server, such as the registrar's. The transfer lock is checked using RDAP. When there's time, the domain's live DNS (its name servers, IP addresses, and mail servers) is also looked up through your server's own DNS resolver, whose operator can see the names being checked. Domains are checked about once a week, and daily in the last 60 days before they expire. A failed check is tried again after a day, then less often each time, up to 30 days, and a domain whose RDAP or WHOIS server is busy waits an hour. See Refreshing Domains.
  • Check Watch List (every 10 minutes): as of v4.27.0, checks the domains on the Watch List with public RDAP and WHOIS servers, a few at a time: weekly while a registered domain is far from expiry, daily in its last 60 days before expiry and in most other stages, and every few hours once it's close to dropping.

As of v4.26.0, Last run of cron.php on the Task Scheduler page shows when cron.php last ran, or Never. When you upgrade to v4.26.0, Last run of cron.php is set to the time of the upgrade if the Task Scheduler had run before, so a working cron job isn't reported as stopped before its next run. If any tasks are enabled and cron.php last ran more than two hours ago, administrators see a warning on the Dashboard and the Task Scheduler page, with a link to the cron job instructions. Until it runs again, expiration emails and the Import Queue only run when you use Run Now. If tasks are enabled and cron.php has never run, the Task Scheduler page shows a note explaining how to set it up, and administrators see it on the Dashboard too whenever the Getting Started checklist isn't shown. If every task is disabled, neither page warns you.

As of v4.25.0, each daily task runs at the same local time all year, including across daylight saving time changes. When you set a daily task's run time, it's saved in your own time zone (from your user settings), and the Task Scheduler page shows each daily task's run time along with its time zone. Changing your time zone later doesn't move tasks that are already set, so set their run times again if you want them to follow your new time zone. When you upgrade to v4.25.0, existing daily tasks keep running at the same moment, using the time zone of the user who installed DomainMOD (or of the first administrator).

Tools

As of v4.23.0, to check that DomainMOD can send email, open Administration -> Tools and click Send Test Email. A test email is sent to your own email address.
